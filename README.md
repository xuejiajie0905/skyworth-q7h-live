# 创维 Q7H 直播配置

自用电视直播配置与检查工具。视频由播放器直接请求频道官方服务；此仓库不存储或转播视频。

## 当前进度

2026-10-26：五个本地频道已通过电脑端候选可行性检查；电视实播验收进行中，尚未完成整体验收。播放器为 MyTV 官方正式版 V2.2.0.219。用户将本地频道连续监测标准改为每台 15 分钟，央视仍每台 10 分钟。河南卫视通过远程订阅镜像观察约 29 分钟，三图审核及用户画面、声音确认，满足新时长标准。河南都市完成约 904 秒观察和三图审核，声音按用户要求作一致假设，正常返回已停止音轨并释放焦点。河南民生监测中。央视网页候选已有独立 10 分钟观察，但起播与退出资源回归尚未通过，未加入正式频道目录。后续音画一致按用户要求作假设，最终听测待用户自行验收，不记为人工确认。

目前本地源的实际解码结果：河南卫视、河南都市、河南民生、郑州新闻综合主线为 1920×1080；郑州都市生活为 1280×720。电视面板支持 4K 不代表这些源为 4K。郑州新闻综合另有官方 720p 备用，其他本地频道暂只有一个已部署入口。都市生活的电脑测试曾遇到连接中断，启用常规网络重试后完成 380 秒解码，电视长期稳定性仍待验收。

## 数据与代码

- `scripts/dxxw-v1.js`：大象新闻公开匿名客户端流程，电视本地获取临时地址。
- `scripts/zzbrtv-v2.js`：郑州广电会面公开直播接口；兼容播放器旧版字符串参数。
- `scripts/cctvnews-v2.js`：央视新闻公开 H5 正常直播流程；拒绝试看、禁播和 DRM 媒体。

脚本使用播放器内置 QuickJS 和官方文档的 `mytv` API。后续维护不自动下载安装播放器 APK，不自动接收第三方脚本变化。

## 已发布接口

- [channels.m3u](https://raw.githubusercontent.com/xuejiajie0905/skyworth-q7h-live/main/channels.m3u)：当前五个本地频道；同名频道的不同线路由播放器合并。
- [channels-cdn.m3u](https://xuejiajie0905.github.io/skyworth-q7h-live/channels-cdn.m3u)：GitHub Pages 发布、jsDelivr 固定提交脚本的分发镜像；用于电视直连原始文件超时的场景。镜像与原订阅由同一生成器构建，镜像并非视频源。
- [epg.xml.gz](https://raw.githubusercontent.com/xuejiajie0905/skyworth-q7h-live/main/epg.xml.gz)：北京时间 XMLTV。河南三台采用 `mytv-android/myEPG` 的精确频道映射，过滤时间倒置、过期和重复条目。郑州两台目前只显示“暂无节目单”占位提示，不虚构节目名称。
- [health.json](health.json)：检查时间、每条线路状态及节目单状态。云端抽样结果不能代替家庭网络和电视实播验收。
- [catalog.json](catalog.json)、[resolvers.json](resolvers.json)：已选频道、固定脚本提交和 SHA-256。

央视新闻 H5 脚本候选在电脑测试中出现约三分钟后 HTTP 403，尚未通过持续播放，因此没有作为合格线路加入订阅。MyTV 内的央视网官方网页候选 CCTV-1、CCTV-4、CCTV-13 已分别完成当次约 604 秒观察及用户声音确认，电视解码统计均为 1280×720。CCTV-1 首次起播超过 20 秒目标；网页播放按主页退出后仍保留音频焦点，需继续回归。以上候选暂不发布，网页路径也不能承诺 1080p 或 4K。

## 维护

GitHub Actions 计划在北京时间 **07:10、19:10** 运行，另有手动运行入口；平台可能延迟调度。检查公开目录、HLS 列表是否更新、少量真实分片、配置重复和脚本完整性，然后过滤 XMLTV。整个流程不上传临时视频地址或媒体样本。

官网网页线路要求目录内已有明确日期的 10 分钟设备观察、截图审核、用户声音确认，以及起播目标和退出资源回归通过。云端对这些线路只检查官网页面响应，标记 `official_web_page_only`、`live_media_checked=false`，不会把 HTML 200 计成视频检查通过。`subscription_checks_passed` 表示当前订阅检查规则通过，`video_checks_passed` 仅包含真实媒体抽样；`all_checks_passed` 是发布规则结果，不能替代电视整体验收。

只有全部当前必需频道和节目单检查通过，才发布频道配置变更。检查失败保留已有合格频道配置，更新 `health.json` 并将工作流标为失败。节目单单独校验：当频道配置与上一版完全一致、节目单自身检查通过时，仍可刷新节目单，避免云端地域/网络限制让节目预告停止更新；节目单下载或语法失败时保留旧节目单。上游改版仍可能需要人工处理。停用 60 天的公共仓库计划工作流可能被 GitHub 暂停，应检查 Actions 是否仍启用。

如精确映射的节目单跨日后到期，生成器保留有效历史条目，并明确显示“暂无节目单”。`epg.stale_upstream_mapping_channels` 记录到期频道，`programme_data_complete=false` 表示实际节目预告不完整；这不等于视频线路失败，也不能被解释为节目预告齐全。下载失败、映射被删除或 XML 无效仍会保留上一份文件。

仓库只使用 Node.js/Python 标准库及固定提交的 GitHub 官方 checkout；不动态执行第三方解析脚本。订阅引用解析器的不可变提交地址，脚本变化必须审阅、重新测试并更新 `resolvers.json`。

## 观看与回退

从电视原桌面的应用入口打开 MyTV，在“河南郑州”分组中选台。上下键换台，确定键打开选台；收藏和线路选择见[播放器文档](https://mytv-android.github.io/mytv-doc/)。准确遥控操作以本机验收记录为准。

订阅和解析器仍需要互联网。部署时还保存一份应用本地订阅及脚本，供订阅服务不可达时手动切换；它们不能保证已失效的官方媒体仍可播放。家庭电脑不参与日常取流。订阅缓存为 12 小时；文档说明过期加载时重新下载、失败时回用旧缓存，本机故障模拟尚在进行，不能把该缓存期限当成独立定时刷新的验证结果。

部署只新增普通播放器，关闭开机自启、后台播放、画中画和刷新率切换。出现原功能异常时先退出/停止本播放器，必要时通过普通应用管理卸载它；不执行恢复出厂、Root 或刷机。部署前清单只用于比较和撤销本次新增内容，不是固件备份。

## 来源与使用边界

- 大象：[官方电视入口](https://static.hntv.tv/kds/)、[已知郑州页面](https://static.hntv.tv/total/television/?id=197)。网页试看入口与本仓库使用的匿名客户端目录不同。
- 郑州广电：[官方手机站](https://m.zzbrtv.cn/)，公开接口域名 `api.zzbrtv.cn`。
- 央视新闻：[官方频道分享页](https://m-live.cctvnews.cctv.com/live/landscape.html?liveRoomNumber=11200132825562653886)。遵守正常播放状态和地域/节目版权限制。
- 播放器：[官方 Release](https://github.com/mytv-android/mytv-android/releases/tag/V2.2.0.219)、[使用文档](https://mytv-android.github.io/mytv-doc/)。
- 协议审阅参考：[Any2parse 固定版本](https://github.com/wjxgzz/Any2parse/blob/240a184cbae216300f8cce937f016ada5fc096e8/dxxw.php)、[mytvJS 固定版本](https://github.com/mytv-android/mytvJS/tree/26102f6f8ac5dea32e6e8d8410f80e2f45950808)。没有自动执行这些上游代码。

免费服务可能改版、限时或停播。缓存无法延续已经失效的视频服务。不得把公网地址可访问理解为转播授权。

本仓库不收集家庭地址、电视标识、账号或 Cookie；服务器临时签名仅留在请求进程中。家庭部署记录和安装包不在此仓库。
